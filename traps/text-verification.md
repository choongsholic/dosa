# 텍스트 검수 함정 — 보고 전 마지막 게이트

## 왜 이 단계가 필요한가

도사 변환은 두 모드를 한 머리로 돌린다:
- **생성 모드** — 입력 자료를 가이드 톤대로 슬라이드 레이아웃에 욱여넣는다. 주의력은 *카드/표 선택, 위계, 페이지 분할* 에 쏠려있다.
- **검증 모드** — 셀 안 텍스트가 *말이 되는지* 한 토큰씩 의심한다.

생성 모드만 돌리면 셀을 다 채워도 *"유물 시간", "후산휴가", "1일 보"* 같은 입력 잔재가 그대로 박힌다. 사용자가 "어때?" 하고 물어야 그제서야 검증 모드로 넘어가서 잡아내는데, 그건 사용자가 두 번 일하게 만드는 거다. **변환 직후 작업물 안에서 반드시 검증 모드를 한 번 명시적으로 돌려야 한다.**

## 검수 5종 (보고 전 필수)

### 1. 베이스 템플릿 잔재
이전 베이스 HTML(`dosa-base/dashboard.html`)의 메타·잔재 토큰이 본문 외 영역에 남았는지:
- `<title>` 태그 — 다른 덱 제목이 그대로 박힌 경우 자주 발생
- `<meta name="description">` — 있다면 갱신
- `<span class="slide-total">` 의 정적 fallback 숫자가 실제 슬라이드 수와 다른지 (JS가 갱신해도 정적값은 맞춰주는 게 깔끔)
- `data-orig-idx` 가 0부터 연속인지
- localStorage 키 prefix 가 `<work>-` 로 치환됐는지 (`new3-dashboard-` 잔재 X)

### 2. 압축·오염된 입력 표현
음성 입력·OCR·메모 압축에서 나오는 어색한 단어. 통상 의심 패턴:
- 발음 유사 오타: 출산↔후산, 운구↔유물, 운영↔유영, 환경↔한경
- 동음이의 한자: 한(限/閑/恨) — 어떤 의미인지 모호하면 한자 병기 또는 풀어쓰기
- 사내 약어가 아닌데 약어처럼 잘려있는 경우 ("1일 보" 같은 정체불명 토막)
- "→", "·" 만 있고 뒤가 비어있는 끊김

→ **이상해 보이면 사용자에게 한 줄 묻기**: *"p4 '유물 시간'이 운구/발인을 의미하는지 확인 부탁드려요"* — 추측해서 고치지 말 것.

### 3. 끊긴 텍스트 / 잘린 단위
- 단위 뒤가 비어있는 경우: `"1단 30 · 2단"` 처럼 두 번째 항목이 잘림
- rowspan/colspan 셀 병합 후 한쪽 셀만 채우고 끝낸 경우
- 카드 body 마지막 줄이 명사로만 끝나 의미가 안 닫히는 경우

### 4. 도메인 상식 체크
입력에 적힌 숫자/룰을 그대로 옮기지 말고 **통상 관례와 충돌하는지 1차 필터링**:
- 휴가 일수 (출산휴가 본인 90일 / 배우자 10~20일 같은 표준)
- 경조금 단위 (만원/원 단위 혼동)
- 날짜 형식 일관성 (YYYY.MM vs YYYY-MM)
- "남성/여성" "본인/배우자" 같은 라벨이 입력 그대로 뒤바뀐 채로 옮겨졌는지

→ 충돌 의심되면 사용자에게 *"p6 출산 행 '90일(남성)' 인데 통상은 본인(여성) 90일/배우자 단기 — 입력대로 둘까요 확인할까요?"* 식으로 명시.

### 5. 표현 일관성
같은 룰·정책이 여러 슬라이드에 다르게 적힌 곳:
- 예: 파견직 룰이 p3 주석 "모든 항목 화환" / p8 본문 "결혼 시 본인·자녀 화환 / 1회 1일" 처럼 따로 등장
- 회사가 둘 이상이면 (예: 현대카드+현대커머셜) 정책 차이 구분이 명시됐는지, 아니면 "양사 공통" 명시
- 같은 컬럼 헤더가 표마다 다른 라벨로 적혀있지 않은지 ("경조" vs "경조사상")

## 검수 보고 형식

검수에서 잡힌 게 있으면 결과 보고에 **별도 섹션** 으로:

```
검수에서 잡힌 N건:
- p4 "지방 배송 시 1단 30 · 2단 …" — 끝이 잘림, 입력 자료 재확인 필요
- p5 "유물 시간" — 운구/발인 오타 가능성
- p6 출산 휴가 90일(남성) — 본인/배우자 뒤바뀐 것 같음
고칠까요? 아니면 입력 자료 다시 확인하고 알려주실래요?
```

추측해서 자동으로 고치지 말 것 — 사용자 확인 받고 수정.
